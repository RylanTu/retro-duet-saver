# 缓存资源占用实测（2026-10-30）

对照：HEAD a046b10 的缓存前源码与当前本地缓存预览源码，使用同一测试入口分别编译。不是只关闭磁盘读取开关，因为当前版仍有签名内存复用。

## 环境和方法

- CPU：Intel Core Ultra 9 275HX，24 个逻辑处理器。
- 显卡：RTX 5080 Laptop GPU / Intel Graphics，WPF Tier 2。
- 同一台电脑，1600 × 1000 无边框 WPF 窗口，目标 60 FPS，速度 100，动画开启，灯光关闭。不更改用户设置。
- 每轮 48 个约一秒采样，六个片段各八秒：Mac 时钟（24）、Mac 签名（311）、Windows 签名（813）、Windows 纸牌（750）、Mac 控制面板（1205）、Windows 画图扩展场景（1285）。括号为路线起始秒。
- 顺序：缓存前第一轮 → 空目录冷缓存 → 热缓存第一轮 → 缓存前第二轮 → 热缓存第二轮。每次新进程；热缓存复用同一构建的磁盘数据。
- CPU 为进程处理器时间增量 / 实际采样时长 / 24，表示整机百分比。
- 内存为进程 working set 和 private bytes；GPU 使用 Windows GPU Engine 中本进程 3D 引擎计数器，显存取 GPU Process Memory。GPU 排除进程启动前五秒；本次每轮只有一个 3D 引擎实例。
- 定时器切换片段，保留正常实时渲染；不是 PNG 导出或离线渲染。

## 结果

缓存前 / 热缓存为各两轮均值；冷缓存仅一轮。内存单位 MiB。

| 指标 | 缓存前 | 冷缓存 | 热缓存 | 热缓存变化 |
|---|---:|---:|---:|---:|
| CPU 整机占用 | 0.7297% | 0.8356% | 0.6250% | -14.34%，绝对 -0.1047 个百分点 |
| GPU 3D | 1.2697% | 1.2888% | 1.2787% | 未测出下降 |
| 工作集 | 409.24 | 418.63 | 403.81 | -5.43 MiB（-1.33%） |
| 私有提交内存 | 560.85 | 563.02 | 547.57 | -13.28 MiB（-2.37%） |
| 专用显存 | 153.61 | 147.92 | 150.08 | -3.53 MiB，幅度小 |

CPU 单轮：缓存前 0.7532% / 0.7061%；热缓存 0.6638% / 0.5863%。按对应轮次比较约下降 11.9% / 17.0%。GPU 单轮区间重叠，不应把微小差异解释成优化收益。

界面构建耗时约 2.08 / 2.04 秒（旧版）；冷缓存 2.21 秒。此指标只覆盖测试入口创建界面，不代表从启动到首帧的延迟。

## 解读与范围

热缓存减少了 CPU 生成工作，内存略降，GPU 持续渲染开销基本不变。首次生成、压缩和写入文件会增加 CPU 工作。

这是一台机器上六个短片段的两轮对照，包含场景加载与切换，并非完整路线或长时间稳定负载；也未测试双屏全屏 / 4K。后台任务和温度没有完全隔离。约 14% 是本次观测均值，不是所有场景的保证。

测试记录的 UI callbacks 是 WPF CompositionTarget.Rendering 回调，旧版约 94.27 次/秒，热缓存约 95.76 次/秒；不是程序实际更新帧数，也不是 GPU 呈现 FPS，不能据此声称帧率提高。双方相同目标帧率，未做 PresentMon 呈现时序测量。

原始 CSV、meta 和汇总 JSON：`output/cache-benchmark/`。测试入口：`tests/CacheBenchmark.cs`；采集脚本：`tests/Measure-Cache.ps1`；汇总：`tests/Summarize-Cache.py`。测试没有修改生产渲染逻辑，也没有发布或推送。
